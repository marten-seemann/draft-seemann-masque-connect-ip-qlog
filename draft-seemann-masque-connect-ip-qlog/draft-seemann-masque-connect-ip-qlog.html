qlog Definitions for CONNECT-IP

Abstract

This document defines qlog events for CONNECT-IP packet processing and representations for its capsules, including the DNS and PREF64 configuration extensions. It extends the HTTP event schema defined in the HTTP/3 qlog document.¶

1. Introduction

CONNECT-IP ([CONNECT-IP]) uses capsules to exchange address assignments, address requests, and routing information. [CONNECT-IP-DNS] defines additional capsules for DNS and PREF64 configuration.¶

This document defines how these capsules and IP packet processing are represented in qlog ([QLOG-MAIN]). Packet events record forwarding decisions for inputs from the peer and the local application, including rejected inputs and generated ICMP responses. Capsule representations use the HTTP events defined in [QLOG-HTTP].¶

2. Conventions and Definitions

The key words "MUST", "MUST NOT", "REQUIRED", "SHALL", "SHALL NOT", "SHOULD", "SHOULD NOT", "RECOMMENDED", "NOT RECOMMENDED", "MAY", and "OPTIONAL" in this document are to be interpreted as described in BCP 14 [RFC2119] [RFC8174] when, and only when, they appear in all capitals, as shown here.¶

The data types are defined using CDDL ([CDDL]). The uint8, uint16, uint32, uint64, hexstring, and RawInfo types are defined in [QLOG-MAIN]. ECN is defined in [QLOG-QUIC].¶

3. Event Schemas

The schemas defined in Section 4 and Section 5 extend the http namespace defined in [QLOG-HTTP]. Implementations SHOULD include the URIs of the schemas they use, together with the HTTP event schema URI, in the trace's event_schemas field, as described in Section 8 of [QLOG-MAIN].¶

3.1. Draft Event Schema Identification

This section is to be removed before publishing as an RFC.¶

Until this document is published as an RFC, implementations MUST NOT use the unversioned event schema URIs. Instead, they MUST append a hyphen and the two-digit draft number to each extension identifier. For draft 00, the URIs are urn:ietf:params:qlog:events:http#connect-ip-00 and urn:ietf:params:qlog:events:http#connect-ip-dns-00.¶

3.2. Capsule Encoding

Capsule representations extend the $HTTPCapsule type socket defined in Section 7.1 of [QLOG-HTTP].¶

These representations are used in the capsule field of http:capsule_created and http:capsule_parsed events. The event's stream_id identifies the CONNECT-IP request stream, allowing multiple sessions and application protocols to share a trace.¶

Sequence fields preserve the order of entries in the capsule. Empty sequences are represented by empty arrays. Integer fields contain their numeric values without the variable-length integer encoding.¶

In capsule representations, the optional raw field uses RawInfo. Its length includes the capsule's Type, Length, and Value fields; payload_length is the length of the Value field. Both exclude HTTP DATA frame headers.¶

4. CONNECT-IP Schema

This schema defines capsule representations and packet processing events for [CONNECT-IP]. Its URI is urn:ietf:params:qlog:events:http#connect-ip.¶

4.1. Capsules 

ConnectIPCapsule = ConnectIPAddressAssignCapsule /
                   ConnectIPAddressRequestCapsule /
                   ConnectIPRouteAdvertisementCapsule

$HTTPCapsule /= ConnectIPCapsule
¶

4.1.1. ADDRESS_ASSIGN

ConnectIPAddressAssignCapsule represents the ADDRESS_ASSIGN capsule defined in Section 4.7.1 of [CONNECT-IP]. Each assigned address records its Request ID and IP prefix.¶

ConnectIPAddressAssignCapsule = {
    capsule_type: "address_assign"
    assigned_addresses: [* ConnectIPAddress]
    ? raw: RawInfo
}

ConnectIPAddress = {
    request_id: uint64
    ip_prefix: IPPrefix
}
¶

Unsolicited assignments retain Request ID 0. Refused assignments retain the prefix 0.0.0.0/32 or ::/128, as specified in Section 4.7.2 of [CONNECT-IP].¶

4.1.2. ADDRESS_REQUEST

ConnectIPAddressRequestCapsule represents the ADDRESS_REQUEST capsule defined in Section 4.7.2 of [CONNECT-IP]. Each requested address records its Request ID and requested IP prefix, including an unspecified address when the sender has no preference for a particular address.¶

ConnectIPAddressRequestCapsule = {
    capsule_type: "address_request"
    requested_addresses: [+ ConnectIPAddress]
    ? raw: RawInfo
}
¶

4.1.3. ROUTE_ADVERTISEMENT

ConnectIPRouteAdvertisementCapsule represents the ROUTE_ADVERTISEMENT capsule defined in Section 4.7.3 of [CONNECT-IP]. Each range records its inclusive start and end addresses and its IP Protocol value. A protocol value of 0 retains its meaning of allowing all protocols.¶

ConnectIPRouteAdvertisementCapsule = {
    capsule_type: "route_advertisement"
    ip_address_ranges: [* ConnectIPAddressRange]
    ? raw: RawInfo
}

ConnectIPAddressRange = {
    start_ip: IPAddress
    end_ip: IPAddress
    ip_protocol: uint8
}
¶

4.2. Packet Processing

The http:connect_ip_packet_processed event (Base importance) records an IP packet after processing, its forwarding decision, and any generated ICMP response. stream_id identifies the CONNECT-IP request stream. forwarded means handed to the application or accepted by HTTP for transmission.¶

ConnectIPPacketProcessed = {
    stream_id: uint64
    source: "application" / "peer"
    packet: ConnectIPPacket
    outcome: "forwarded" / "dropped"
    ? reason: "invalid" /
              "source_address_not_allowed" /
              "destination_address_not_allowed" /
              "protocol_not_allowed" /
              "hop_limit_exceeded" /
              "packet_too_large" /
              "send_error" /
              "other"
    ? icmp_response: {
        to: "peer" / "application"
        packet: ConnectIPPacket
    }
    * $$http-connectippacketprocessed-extension
}

$ProtocolEventData /= ConnectIPPacketProcessed
¶

source identifies the input as coming from the application or peer. packet describes it before forwarding changes. icmp_response records a generated response and its destination.¶

Capsule and packet events SHOULD be ordered to reflect the address and route state used for each decision. A local change can take effect when its capsule is created and queued.¶

4.2.1. IP Packets

Header fields retain their wire values; unavailable fields are omitted. IPv6 extension headers appear in wire order. upper_layer_protocol identifies the protocol after them.¶

For raw, length is the observed packet length, payload_length excludes IP and extension headers, and data may contain a prefix of the packet.¶

ConnectIPPacket = {
    ? header: ConnectIPIPv4Header / ConnectIPIPv6Header
    ? extension_headers: [* ConnectIPIPv6ExtensionHeader]
    ? upper_layer_protocol: uint8
    ? icmp: ConnectIPICMP
    ? raw: RawInfo
}
¶ 
ConnectIPIPv4Header = {
    version: 4
    ? ihl: uint8
    ? dscp: uint8
    ? ecn: ECN
    ? total_length: uint16
    ? identification: uint16
    ? flags: uint8
    ? fragment_offset: uint16
    ? ttl: uint8
    ? protocol: uint8
    ? checksum: uint16
    ? source_address: IPAddress
    ? destination_address: IPAddress
    ? options: RawInfo
}
¶ 
ConnectIPIPv6Header = {
    version: 6
    ? dscp: uint8
    ? ecn: ECN
    ? flow_label: uint32
    ? payload_length: uint16
    ? next_header: uint8
    ? hop_limit: uint8
    ? source_address: IPAddress
    ? destination_address: IPAddress
}

ConnectIPIPv6ExtensionHeader = {
    type: uint8
    ? raw: RawInfo
}
¶

4.2.2. ICMP

quoted_packet describes the packet quoted by an ICMP error. mtu is the advertised MTU for Packet Too Big or Fragmentation Needed. ICMP raw excludes the IP header; payload_length excludes the ICMP header.¶

ConnectIPICMP = {
    ? type: uint8
    ? code: uint8
    ? checksum: uint16
    ? mtu: uint32
    ? quoted_packet: ConnectIPPacket
    ? raw: RawInfo
}
¶

5. DNS and PREF64 Capsule Schema

This schema defines representations for the capsules in [CONNECT-IP-DNS]. Its URI is urn:ietf:params:qlog:events:http#connect-ip-dns.¶

ConnectIPDNSCapsule = ConnectIPDNSAssignCapsule / ConnectIPPREF64Capsule

$HTTPCapsule /= ConnectIPDNSCapsule
¶

5.1. DNS_ASSIGN

ConnectIPDNSAssignCapsule represents the DNS_ASSIGN capsule defined in Section 3.4 of [CONNECT-IP-DNS]. Each configuration records its nameservers, internal domains, and search domains.¶

ConnectIPDNSAssignCapsule = {
    capsule_type: "dns_assign"
    dns_configurations: [* ConnectIPDNSConfiguration]
    ? raw: RawInfo
}

ConnectIPDNSConfiguration = {
    nameservers: [* ConnectIPDNSNameserver]
    internal_domains: [* text]
    search_domains: [* text]
}

ConnectIPDNSNameserver = {
    service_priority: uint16
    ipv4_addresses: [* IPAddress]
    ipv6_addresses: [* IPAddress]
    authentication_domain_name: text
    service_parameters: [* ConnectIPDNSServiceParameter]
}

ConnectIPDNSServiceParameter = {
    key: uint16
    value: hexstring
}
¶

Domain names retain the presentation format used in the capsule, including empty strings where permitted by [CONNECT-IP-DNS]. Each service parameter records its numeric SvcParamKey and its SvcParamValue wire bytes as a hexadecimal string. Parameters are listed in ascending key order.¶

5.2. PREF64

ConnectIPPREF64Capsule represents the PREF64 capsule defined in Section 4.1 of [CONNECT-IP-DNS]. The 96 address bits carried in the capsule are followed by 32 zero bits to form the IPv6 address.¶

ConnectIPPREF64Capsule = {
    capsule_type: "pref64"
    prefixes: [* IPPrefix]
    ? raw: RawInfo
}
¶

6. Common Data Types

These types are shared by both event schemas.¶

6.1. IPAddress 

IPAddress = text / hexstring
¶

An IP address can be represented as text, hexadecimal bytes, or a redacted value. Human-readable IPv4 and IPv6 addresses use dotted-decimal notation and [RFC5952], respectively.¶

6.2. IPPrefix 

IPPrefix = text
¶

An IP prefix is a textual address, a slash, and a decimal prefix length, for example 192.0.2.0/24 or 2001:db8::/64.¶

7. Security Considerations

The security and privacy considerations in [QLOG-MAIN] apply. Headers, configuration, and raw data can reveal network topology, user activity, and application data. Implementations should minimize capture and protect logs.¶
